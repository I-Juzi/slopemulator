# 14 — Client.exe 381: UI framework, system messages and commands

Summary:

1. The UI is not Scaleform. The widget system is in the engine DLL `bsengine_Shipping.dll`. `Client.exe` uses it through one interface object, `UIEngineInterface` (501 virtual slots). `LoadEngine` `0x114c6d0` gets it from the DLL export `UIEngineInterfaceGetInstance` and keeps the function pointer at `0x1a4c0cc`.
2. The client side has about 930 UI classes and 15,700 named functions. The root object is `Ui` (`BNSClient::GetUi` `0x401600`). It holds one `BUiBase` per `BUiBase::UI_TYPE` (intro, lobby, world, arena lobby, loading, guild customize, replay, outro). Each panel is a `UIPanel` (vtable `0x1685418`) with an engine widget id.
3. The engine sends widget events (`EUiEvent`, 103 `EventType` values) back to the client through `EventTransmitter::Transmit` `0x55fbe0`. Panels register static `On…(EngineEventHandler *, EUiEvent *)` callbacks per widget id.
4. All system and error texts go through `World::InvokeGameMessage` (11 overloads, about 3,300 call sites). The argument is a text alias `Msg.…` (2,792 aliases in the exe). The alias selects a `GameMessage` data record, and the record selects chat, headline, sound and history channel. Server error codes map to aliases in `switch` blocks in each feature handler. [`14-ui-msg-cases.tsv`](14-ui-msg-cases.tsv) lists 2,822 such uses.
5. Slash commands typed in chat come from the data table `UserCommand` (localized words, 53 command types). `ChatInputPanel::processChatFunctionWorldByEnterKey` `0x118ce60` runs them. The 12 names at `0x1955858` are **not** UI button commands: they are option names for the mouse button bindings (`LBtnCmd` … `HybridModeRBtnCmd`).

How the TSVs were made: one IDA Python script per file in this slice. The switch scan of `14-ui-msg-cases.tsv` reads the Hex-Rays text of each of the 1,027 functions that refer to a `Msg.*` string. It keeps a stack of `switch ( … )` lines and the last `case` labels. Rule for `switch_expr`: `packet_cmd(vtbl+12)` = the packet command (virtual call `+12`, see [05-game-dispatch](05-game-dispatch.md)); `i16 @+16` = a 16-bit field at packet offset 16 (the usual error-code field). Other expressions are the raw Hex-Rays text (often a local variable that holds the packet command or the error code). A row with an empty switch is an alias outside a switch (an `if` branch or a plain call).

## 1. UI system

### 1.1 What the UI is

- No Scaleform, no Flash, no Lua in the exe ([00-inventory](00-inventory.md) §1). The widgets, layouts, fonts and textures are in UE packages that the engine DLL loads.
- `Client.exe` holds the logic of each panel. It reads and writes widget values through `UIEngineInterface` by widget id (`unsigned int`).
- A panel or widget is found by name: `UIPanel::GetWidgetId` `0x7fbe40` looks up a `std::map<std::wstring, unsigned int>`. `UIPanel::setWidgetIdByFormat` `0x7ead00` and `UIUtil::SetWidgetId` `0x7f7030` fill ids for widget names made with a format string.

### 1.6 Client → game code and network

A panel callback calls game objects directly. The game object builds the packet. Examples from §3.2: `UiPartyManager::InviteTargetByName`, `Guild::RequestInviteGuild`, `UiTradeManager::InviteTradeByName`, `Friends::RequestProposal`. The packet layouts are in the feature chapters ([09-items](09-items.md), [11-social](11-social.md), [12-infogate-arena](12-infogate-arena.md)).
