## Goal
Write chapter `Docs/Platform/StServers/RE/11-auction-virtualcurrency-wish.md` of the full reverse-engineering reference for the StServers (NP platform) programs. The reference replaces IDA for the Rust port. Be complete and exact: addresses, enums, field layouts, timers, log strings.

## Method (framework filter)
All StServers programs link the same framework. `Docs/Platform/StServers/RE/00-framework.md` (slice `st-00`) describes it. Do not reverse framework code again.
- Read the "Quick find" and "Service recipe" sections of `00-framework.md` first. Read other sections only when you need them.
- In each database, first run `exec(open("<worktree>/tools/fn_fingerprint.py").read())`, then `apply_names("<worktree>/Docs/Platform/StServers/RE/framework-names.tsv")`.
- `Docs/Platform/StServers/RE/funcs/<binary>.tsv` lists the service functions of each binary (hash, address, size, instruction count, name, `shared_with` = number of other binaries that have the same function). Only these functions are your work. Do not read the file in full: use `rg`, or load it in IDA Python and filter it.
- Use the "Service recipe" snippets to list the commands, procs, config keys and timers. Then go through the handlers.
- When service code calls a framework function, use its name and its section in `00-framework.md`. Open it in IDA only if the chapter does not answer your question. Then add the missing fact to the "Framework gaps" section of your chapter.
- If the recipe fails on a binary, say so in the handoff, and find the command table by hand.

## Work (for each service)
1. **Role:** what the service does, who calls it (other services, gates, client), and its config keys (every key, default and use).
2. **Commands:** every command that the service handles: name or id, request fields, reply fields, error codes, the handler address, and what the handler does step by step (checks, DB calls, calls to other services, state changes).
3. **DB procs:** every proc that the service calls: name, database, parameters, result use, call site.
4. **State and timers:** caches, in-memory tables, timers (period in ms), background jobs, limits and counters.
5. **Calls out:** every call to another service: target, command, when and why.
