## Lookup design (the main use of this chapter)
The reader uses this chapter instead of IDA, or to jump in IDA to the right address at once.
- Start the chapter with a "Quick find" table: task or question → function name → 381 address → GM name → section link. Example row: "where the client sends a move" → `MoveListMaker::Send` → `0x…` → same → §2.
- Give the 381 address for every function, global, vtable and string that you name. Write addresses as `0x` + hex so `grep` finds them.
- Give the search anchors: unique strings, constants and command ids that lead to each function.
- Each `.tsv` has a header row and an address column, so `grep`, `awk` and IDA scripts can use it directly.

## Detail level (very detailed; this is the main goal)
- Cover every function of the area that has a name or a string, not a sample. Use one IDA Python script to list them, then work through the list.
- For each packet or message: id, direction, every field (offset, size, type, meaning, valid values), the handler or builder address, and what the client does with it.
- For each state machine: every state, event, transition, timer value in ms, and log string.
- For each enum or table: every value. Put long lists in `.tsv` files (no row limit).
- For each subsystem: a call-flow diagram from the entry point to the network or the screen.
- Give one worked example (bytes or field values) where a packet layout is known.
- If you run out of turns, write what is left in the handoff "Not done" list with addresses, so a follow-up slice can continue. A chapter with gaps listed is better than a short chapter.
